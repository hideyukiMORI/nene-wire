# 要件と施主の決定 — NeNe Wire

> Status: normative（規範）/ 2026-10-26 初版
> 施主（hide）が言ったこと・決めたことだけを FR に書く。**施主が言っていない機能を要件に書かない・実装しない。**
> 施主の上流指示は「叩き台。アイディアなので絶対指示ではない」とされている。実装側が決めたことは第 2 節に分けて書き、施主から違う指示が来たら従って変え、ADR で置き換える。

NeNe Wire は、WSL2 の Ubuntu の端末（Windows Terminal）で、世界と日本のニュースの見出しと冒頭数行を、ギークでサイバーな演出で一件ずつ表示し続けるツールである（Swift 製）。
使い方はスクリーンセーバーのイメージで、起動したら終了するまでひたすらニュースを流し続ける。外国語のニュースは指定した言語（普段は日本語）に翻訳して表示する。
兄弟の [NeNe Gambit](https://github.com/hideyukiMORI/nene-gambit)・[NeNe Reversi](https://github.com/hideyukiMORI/nene-reversi) と同じ規約・同じ端末の土台で作る。

## 1. 要件（FR）

| ID | 要件 |
| --- | --- |
| FR-01 | 端末で起動したら、終了するまでニュースの見出しと出だし数行を一件ずつ表示し続ける。眺めるためのもので、演出のかっこよさとテンポを重視するが、文字が読めないほど演出を過剰にしない |
| FR-02 | 一晩流しっぱなしにしても落ちず、メモリが増え続けない。ネットが切れても、一部のフィードが取れなくても、翻訳に失敗しても、手元にある記事で表示を続ける |
| FR-03 | どんな終わり方をしても、終了後の端末は起動前と同じ状態に戻る（カーソル・エコー・画面） |
| FR-04 | 日本語がきれいに表示される。全角文字の幅を正しく扱い、折り返しや枠線がずれない |
| FR-05 | アカウント登録や API キーが要るサービスに依存しない。翻訳は登録不要で、できればオフラインで動く手段を使う |
| FR-06 | 記事のページを開いて本文を抜き出さない（RSS / Atom に入っている情報だけを使う）。GUI や Web 画面を作らない。設定は日常的にいじるものだけ |
| FR-07 | 設定で有効にした RSS / Atom フィードを定期的に（15 分おき程度）取りに行く。礼儀正しく取る: 更新がなければ中身を取り直さない・失敗したフィードは間隔を空けて再挑戦する・短い間隔で何度も取りに行かない |
| FR-08 | 記事ごとに見出しと出だしを取り出す。出だしは要約欄から、HTML タグなどを取り除き、先頭の 2〜3 文・長くても 250 文字程度。要約欄が空か見出しと同じなら見出しだけ |
| FR-09 | 記事の言語を判定する。表示したい言語と同じならそのまま、違えば翻訳に回す。判定できなければ原文のまま |
| FR-10 | 見出しと出だしをそれぞれ翻訳する。一度翻訳した結果は保存し、二度と翻訳し直さない。翻訳できなかったものは原文のまま「未翻訳」と分かる印を付けて表示し、あとで再挑戦する |
| FR-11 | 取得した記事と翻訳結果を保存し、次回の起動時にすぐ表示を始められる。1 週間程度より古い記事は自動で捨てる |
| FR-12 | 手元の記事を一件ずつ表示し、最後まで行ったら最新の内容で並べ直して最初から繰り返す。フィードを順番に巡回しながら新しいものから並べ、同じフィードの記事ばかり続かないようにする |
| FR-13 | 取得と翻訳は表示の裏で進め、表示が待たされたりカクついたりしない |
| FR-14 | 表示画面: 中央に枠で囲んだ記事ブロックを一つ置き、一件ずつ入れ替える。ブロックにはフィード名・現在時刻・見出し（翻訳後）・出だし（翻訳後）・原文の見出し（翻訳した場合だけ、控えめに）・記事のリンクを出す |
| FR-15 | 画面の下端に状態を出す: 何件目か／全部で何件か・ネットにつながっているか・翻訳が動いているか（どの言語からどの言語へ・翻訳待ちの件数）・取得に失敗しているフィードがあればその旨 |
| FR-16 | 一件ごとの演出: 枠が描かれる → 見出しがランダムな記号から正しい文字に次々と確定していく → 出だしがタイプライターのように打ち出される → 原文とリンクがふわっと浮かび上がる → しばらく静止 → 走査線が通って消える |
| FR-17 | 静止している間も、ときどき一瞬だけ見出しにノイズのような乱れを入れ、画面が生きている感じを出す |
| FR-18 | 記事ブロックの外側に、暗い色で文字の雨を降らせる（設定でオン／オフ） |
| FR-19 | 色は黒背景に緑の蛍光色が基本。アンバー・シアン・マゼンタなども選べる |
| FR-20 | 起動直後でまだ記事がないときは、ブートログ風のメッセージ（回線を確立中・フィードを取得中など）を実際の進み具合に合わせて流し、何も表示されない時間を作らない |
| FR-21 | 端末の大きさが変わっても表示が崩れたまま残らない。小さすぎるときは「小さすぎる」とだけ表示する |
| FR-22 | 操作: 終了・一時停止／再開・次の記事・前の記事・設定画面を開く（閉じたら表示に戻る）。キーは誤って押しても困らないもの |
| FR-23 | 設定画面（キー操作だけ）のフィードの一覧: 名前と URL（ドメイン程度）で一覧・一件ずつ有効／無効・追加（名前と URL を入力）・名前と URL を直す・削除（確認してから）・選んだフィードをその場で試す（何件取れたか・何語と判定したか・失敗ならその理由） |
| FR-24 | 設定画面の表示の設定: 表示する言語（日本語・英語・中国語・韓国語・フランス語・ドイツ語・スペイン語程度）・一件あたりの表示時間・色のテーマ・文字の雨のオン／オフ・原文の見出しを添えるかどうか |
| FR-25 | 保存せずに設定画面を閉じようとしたら確認する。変更は次の記事から反映されればよい |
| FR-26 | 初回起動時に、国内と海外の主要なニュースのフィードを数本登録しておく。実際に取得できることを確かめたものだけ |
| FR-27 | 翻訳は候補をいくつか比べたうえで提案する。訳の質は「見出しの意味がつかめる」程度で十分で、軽さと安定性を優先する |
| FR-28 | 翻訳の部分は他から切り離し、別の翻訳手段に差し替えたり追加したりできるようにする |
| FR-29 | 翻訳に必要なモデルなどが入っていない場合は、止まらずに原文で表示し、何を準備すれば翻訳されるかが分かるようにする |
| FR-30 | 動作環境: WSL2 の Ubuntu＋Windows Terminal |

## 2. 施主の決定と、実装側が決めたこと

| # | 論点 | 状態 |
| --- | --- | --- |
| Q1 | アプリ名 | **決定**（実装側・施主が任せた）: NeNe Wire（`nene-wire`）。通信社の配信線（newswire）から。兄弟と同じ「NeNe＋短い英単語」 |
| Q2 | 公開範囲とライセンス | **決定**（施主「パブリックリポジトリを作って」）: PUBLIC・MIT（兄弟と同じ） |
| Q3 | Claude Code がこの WSL でシェルを実行してよいか | **決定**（施主の回答 2026-10-26）: よい。上流指示の EDR の制約はこの環境に当てはまらない。ビルド・`make check`・gh・実機の撮影まで行う |
| Q4 | 段階の進め方 | **決定**（施主の上流指示 第 8 節）: ①取得して素のまま一覧 ②表示画面で一件ずつ（演出なし・端末の復元は確実に）③演出 ④取得を裏で・保存 ⑤翻訳 ⑥設定画面。厳格規約の Phase 0〜2 はその前に置く |
| Q5 | 翻訳の手段 | **未決**: 手順 5 で候補（ローカルの翻訳モデル・ローカル LLM など）を実測して比べ、ADR で提案する（FR-27） |
| Q6 | 個人で眺めるためのツールで、翻訳した見出しや要約を外部に公開・再配布しない | **決定**（施主の上流指示 第 7 節）。リポジトリにも記事や翻訳結果を入れない |
| Q7 | Ready・squash merge・Issue の起票 | **決定**（兄弟と同じ扱い）: フルゲートが緑なら確認なしでよい。Release の公開など外に出る操作は確認を取る |

それ以外の具体的な値（キーの割り当て・取得の間隔と再挑戦の間隔・保存の場所・テーマの名前と数・表示時間の初期値・最初のフィード）は、決めた段の ADR に書き、ここに 1 行で足す。
