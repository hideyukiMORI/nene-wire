# ADR 0006 — 表示は端末の幅いっぱい・高さ 15 行の帯に描き、端末を占有しない。幅は Unicode の East Asian Width の表で数える

- 状態: 受理（決定の 1・3・4・5 の帯の置き方（プロンプトの下・相対で描く）、2 の割り付け、10 の取得は ADR 0007 で置き換えた）
- 日付: 2026-10-26
- Issue: #5
- 影響する規則: ARC-002 / ARC-003 / ARC-005 / ARC-006 / ARC-007 / SWF-009 / CNF-010 / CNF-011 / FR-03 / FR-04 / FR-12 / FR-14 / FR-15 / FR-18 / FR-21 / FR-22

## 文脈

上流指示の進め方の 2 段目は「表示画面で一件ずつ切り替わる（演出なし・端末の復元は確実に）」。
兄弟の NeNe Gambit・NeNe Reversi は alternate screen で端末の全面を使う。

施主はデザインのキャンバス（2026-10-26）を見て、方向性（攻殻機動隊のようなサイバーでギークな画面）を承認したうえで、
画面の大きさを「メインの画面は画面の四分の１くらいのサイズ」「幅は100%たかさは15行　とかそう言うかんじ」「とりあえず15行　きめうちにして」と決めた（REQUIREMENTS の Q9）。
ウィンドウの縦横の半分ではなく、**横幅いっぱいで背の低い帯**である。

日本語の見出しと出だしを枠の中に収めるには、文字が端末で何桁を占めるか（全角は 2 桁）を正しく数える必要がある（FR-04）。
Foundation は使えない（SWF-014）ので、Swift の標準ライブラリにある Unicode の性質だけでは East Asian Width が分からない。

## 決定

1. **帯**: 幅は端末の桁数いっぱい（端末の大きさに合わせて伸び縮みする）、高さは **15 行の決め打ち**。alternate screen を使わず、
   起動したときのカーソルの行から下に 15 行を確保する（下に余地が無ければ改行で送り上げる）。帯の左上を `ESC 7` で覚え、
   描くときはそこからの相対で位置を指す（`ESC 8` ＋ `ESC [ n B`）。帯の上のシェルの履歴と、起動時の取得の進み具合の行は残る
2. **帯の中**: 見出しの行（名前・回線の状態・日時）・記事の枠（左）と DATA の窓（右・幅の 18%・11〜35 桁）・状態の行（FR-15）。
   枠の中は受信の行・見出し（2 行まで）・出だし（残りの行）・リンク。収まらなければ `……` で切る。DATA の窓は手順 3 で文字の雨を降らせる場所（FR-18 の読み替え）で、手順 2 では空
3. **終わり方**: `q`・Ctrl+C・SIGTERM・SIGHUP では、ループを抜けて帯の左上へ戻り、そこから下を消し、色とカーソルとエコーを戻す。
   異常終了のシグナル（SIGSEGV など）では、ハンドラがその場で同じ列を書いてから既定の動作で死ぬ（兄弟と同じ形）。終わったあとのプロンプトは帯の左上に出る
4. **大きさが変わったら**（SIGWINCH）: 前の帯を消して確保し直し、全部を描き直す。幅 72 桁未満か高さ 15 行未満なら「小さすぎる」とだけ出す（FR-21）
5. **差分**: 前のフレームと違う行だけを、行の頭から丸ごと書き直す（全角の文字の半分だけを書き換えない）。1 フレーム 1 回の `write`
6. **全角の幅**: 幅を数えるのは Render の `CellWidth` の 1 か所。Unicode 16.0.0 の `EastAsianWidth.txt`（一次資料）から
   `eng/generate-east-asian-width.py` が W・F の範囲の表（`EastAsianWidth.swift`・生成物）を作る。スクリプトはファイルの SHA-256 を確かめてから書く。
   曖昧（A）は 1 桁（Windows Terminal の既定と同じ）。結合文字・囲み記号・書式文字・制御文字は 0 桁（標準ライブラリの一般カテゴリで引く）。
   絵文字の表示を求める異体字セレクタ（U+FE0F）が付いた文字は 2 桁。格子の全角の文字は 2 つのセル（左に文字・右に `continuation`）を占める
7. **折り返し**: Render の `TextLayout` の 1 か所。和文は文字で、欧文は空白で切り（空白の無い長い語は文字で切る）、行頭に句読点や閉じ括弧を置かない（前の 1 文字を連れて送る）
8. **並べ方**: Core の `Lineup`（FR-12）。フィードを順に巡りながら、それぞれ新しい記事から 1 件ずつ取る。同じ識別子の記事は 1 件だけ
9. **操作**（FR-22）: `q` 終了・空白 一時停止と再開・→ 次・← 前。1 件の表示時間は 12 秒。最後の次は最初へ、最初の前は最後へ回る。設定画面のキーは手順 6 で足す
10. **取得**: 手順 2 では起動時に 1 回だけ、帯を確保する前に 1 本ずつ取り、進み具合をふつうの行として出す。裏での取得は手順 4
11. **色**: 既定の PHOSPHOR だけ（値はデザインのキャンバスから）。罫線が 1 桁で描かれない端末では ASCII の枠へ落とす（兄弟と同じ問い合わせ）。24 ビットか 256 色かは兄弟と同じ判定
12. **Terminal の標準モジュール**に `Synchronization` を足す（シグナルの旗の `Atomic`）。ADR 0004 の最後の項「同じ必要が生じた PR で、この ADR を置き換える ADR とともに足す」をこの ADR で実行する

## 強制

- **active** → SwiftPM の target グラフ＋CNF-010 / CNF-011（Render・Terminal を足した依存グラフの正本と `Package.swift` の一致・import の許可リスト。Terminal の `std=` に `Synchronization`）
- テストで確かめる（`make check` の `test` 段）: 帯が 15 行で、72・80・120・160・200 桁のどれでも枠の角と仕切りが同じ桁にそろうこと・全角の幅と折り返し・小さすぎるときの表示・
  ASCII の枠・読ませる色のコントラスト（4.5:1）・キーの意図・差分が帯の左上からの相対で書かれること・並べ方
- 実機で確かめた（2026-10-26・Windows Terminal・120×30）: 帯がプロンプトの下に幅いっぱいで出る。擬似端末で `q`・SIGTERM・SIGSEGV・大きさの変更（120→80→60×10）のどれでも、
  終わったあとの termios が起動前と同じで、帯を消してカーソルを戻す列が最後に出る
- 生成物の表が一次資料と一致していることは、機械では見ていない（**planned**: 生成し直して差分が無いことを確かめる検査は、一次資料をリポジトリに置くかどうかと合わせて決める）

## 結果

- 端末を占有しないので、ほかの作業をしながら下の 15 行で眺められる。終わればシェルの続きに戻る
- 幅が変わっても枠が伸び縮みし、全角の文字で枠がずれない
- 失うもの: 帯の位置は端末の画面のどこにあるか分からないので、相対で描く。端末が大きさの変更で行を組み直す（リフロー）と、覚えた左上がずれることがある。
  そのときは次の SIGWINCH で帯を確保し直すが、古い帯の跡が上に残ることがある

## 却下した選択肢

| 選択肢 | 却下の理由 |
| --- | --- |
| 兄弟と同じ alternate screen で全面を使う | 施主の決定（幅 100%・高さ 15 行）と合わない |
| 記事の枠をウィンドウの縦横の半分にする（最初の読み） | 施主の意図と違った（「今のウィンドウの高さの半分じゃなくて」） |
| 高さを設定で変えられるようにする | 施主が「15行　きめうち」と決めた |
| 帯の位置をカーソル位置の報告で絶対位置として持つ | 応答を待つ往復が要り、送り上げやリフローで結局ずれる。相対で描けば問い合わせが要らない |
| 幅の表を手で書く・`wcwidth` を呼ぶ | 手書きは版が分からない。`wcwidth` は Render から呼べず（Glibc の禁止）、libc の版で答えが変わる |
| 曖昧（A）を 2 桁にする | Windows Terminal の既定は 1 桁で、罫線や `·` が 2 桁に数えられて枠がずれる |
