# ADR 0009 — 演出は「時計と種」から格子を作る Render の純粋な関数にし、デザインのキャンバスの案をすべて入れる

- 状態: 受理
- 日付: 2026-10-26
- Issue: #16
- 影響する規則: ARC-005 / ARC-007 / SWF-013 / CNF-012 / CNF-022 / FR-16 / FR-17 / FR-18 / FR-20 / FR-21 / Q13

## 文脈

施主はデザインのキャンバス（2026-10-26）で演出の案を見て、「もっとギークでサイバーでクールなアニメーション演出が欲しいな。厨二臭あるくらいで」
「一文字ずつ出るとか、その時文字がくるくるかわるとか？」「切り替わる時文字がパラパラ落ちてくとかも。候補出してくれたのいいね。全部入れて」と決めた（REQUIREMENTS の Q13）。
キャンバスの案は A 復号・A1〜A3 くるくる確定・B 電脳ノイズ・C 緊急傍受・D 接続シーケンス・E HUD の呼吸・F パラパラ落ちる切り替え。

PROJECT_LAYOUT は「演出は経過時間と乱数の種から格子を作る純粋な関数」と決めている。並行性は使えない（SWF-013）。

## 決定

1. **時計**: 合成ルートが `Motion`（いまの記事を見せ始めてからのミリ秒・起動してからのミリ秒・記事ごとの種・消えていく前の記事・最初の記事か・1 件の時間・稼働時間・次の取得までの秒）を作って `StripState` に入れる。
   種は合成ルートが記事ごとに `SystemRandomNumberGenerator` から読む（ARC-007）。Render の揺らぎは種と番号から作る純粋な関数（`Noise`・SplitMix64 の混ぜ方）で、同じ状態なら同じ格子になる
2. **時刻割り**（`Choreography` の 1 か所）: 前置き → 確定 → 静止。
   - 前置き: 速報なら緊急傍受の警告（1.6 秒・案 C）、前の記事があれば切り替え（0.9 秒・種で「パラパラ落ちる」案 F か「走査線」案 A）、起動して最初の記事なら枠を左上から時計回りになぞる（0.8 秒・案 A）
   - 確定（2.6 秒）: 受信の行に「復号中 NN%」と進み具合の棒、枠の中の文字が記号のくるくるを経て止まる。止まり方は種で 1 文字ずつ（A1）・左から（A2）・ばらばら（A3）。全角の位置にはカタカナ、半角の位置には 16 進と記号を出すので、くるくるの間も桁がずれない
   - 静止: 電脳ノイズ（案 B）が 2 回だけ 0.24 秒走る（見出しの色ずれ・1 行の横ずれ・ブロックのノイズ・反転の帯・見出しの行に `S1GN4L ▒▒▒▒ L0ST`・MSG に「ゴーストを検知」）
3. **速報**（案 C）: 警告の間は見出しの行に `!! INTERCEPT !!`、枠の中に警告の縞と「INTERCEPT ■ 緊急傍受 ■ PRIORITY: ALPHA」の流れる帯。そのあと受信の行に警告色の `速報`、枠のラベルは `速報 // BREAKING`、枠は警告色で脈打つ。待っている速報の件数は状態の行に出す
4. **起動直後**（案 D・FR-20）: 最初の記事が出るまで枠の中にブートログを 1 秒 60 文字で打ち出す。中身は実際の取得の結果（回線ごとの件数と失敗の理由）で、締めの 2 行（「ゴーストの応答を確認 …… 応答なし」「全回線を掌握。流れを開始する」）だけが決まり文句。DATA の窓には 16 進のダンプが流れる。少なくとも 2.5 秒、ログを打ち終えるまで見せる
5. **常時**（案 E・FR-18）: 見出しの行の空白と区切りの上を光が往復する・枠の色がゆっくり明滅する・受信の印が点滅する・枠の下辺の左が次の記事までの導火線になる・
   DATA の窓のフィードの行の下に文字の雨（FR-18 の読み替え・ADR 0006）と、次の同期までの残り（`SYNC mm:ss`）と稼働時間（`UP hh:mm:ss`）
6. **描く間隔**: 前置き・確定・ノイズの最中は毎秒 30 回、それ以外は毎秒 15 回（`StripRenderer.isBusy`）。違う行だけを書き直すのは変わらない（ADR 0006）
7. **字形**: 演出の字形（縞・ノイズ・走査線・棒・導火線・回転）は `FxGlyphs` の 1 か所。罫線を 1 桁で描けない端末では ASCII に落とす
8. **一時停止**: 記事の時計を止める（くるくるや切り替えはその場で止まる）。常時の演出は動き続ける
9. **#13**: 見出しの行は、収まらなければ飾り（電脳ニュース回線）・日付の順に落とし、時刻は必ず残す。DATA の窓は最低 16 桁

## 強制

- **active** → CNF-012（Render は時計と乱数を読めない。種は合成ルートから）＋CNF-022（並行性の禁止）＋CNF-017（Render から出力しない。`dump` という名前の関数も字句で止まった）
- テストで確かめる（`make check` の `test` 段）: 同じ時計なら同じ格子・種が違えば違う格子・くるくるの最中は見出しが無く止まったあとはある・どの止まり方もどの件数でも確定の長さに収まる・
  切り替えの最初は前の記事があり最後は消えている・速報の警告・ノイズは静止の中に 2 回・最初の記事は枠をなぞる・ブートログの打ち出しと 16 進・HUD が動く・ASCII の端末に罫線とブロックを出さない・流れる帯はちょうどの幅・80 桁でも時刻が残る
- 演出を止めるとテストが落ちることを確かめた（くるくるを無効にすると 2 件が落ちる）
- 実機で確かめた（2026-10-26・Windows Terminal・120×16・`--demo`）: ブートログ・枠をなぞる・復号中とくるくる確定・電脳ノイズ・パラパラ落ちる切り替え・緊急傍受と速報の着地
- 負荷を測った（release・擬似端末・120×30・30 秒）: CPU 1.8%・端末への出力 88 KiB/秒・RSS 11 MB

## 結果

- 施主の「厨二臭あるくらい」の画面になる。演出はすべて文字と色だけで、端末でそのまま描ける
- 失うもの: 常に毎秒 15 回以上描くので、止まっている画面より CPU と端末への出力が増える（上の実測）

## 却下した選択肢

| 選択肢 | 却下の理由 |
| --- | --- |
| 案を 1 つに絞る | 施主が「全部入れて」と決めた |
| 演出の状態を Render の外（合成ルート）に持つ | 時刻からの純粋な関数にすれば、時刻を決めてテストできる。状態を持つと同じ画面が再現できない |
| くるくるの記号を Render の乱数源で選ぶ | Render は乱数を読めない（ARC-007）。種と番号からの純粋な関数で足りる |
| ずっと毎秒 30 回描く | 静かなときは 15 回で十分に滑らか。CPU と出力を半分にできる |
