# ADR 0007 — 起動したら画面を消して最上部の帯に常駐し、裏で取り直し続ける。取得の様子は帯の中に出し、新しく現れた記事は速報として割り込む

- 状態: 受理
- 日付: 2026-10-26
- Issue: #7
- 影響する規則: ARC-005 / ARC-006 / ARC-007 / SWF-013 / CNF-022 / CNF-023 / FR-02 / FR-07 / FR-12 / FR-13 / FR-15 / FR-20

## 文脈

手順 2（ADR 0006）では、起動時に 1 回だけ取得し、その進み具合を帯の上にふつうの行として出していた。施主は実機の写真を見て次のように言った（2026-10-26）:

> リアルタイムでずっと常駐して登録したrssのヘッドラインを流し続けるイメージなんだ。ニュースの下の方によくあるよね。
> だから、取得ログとかは残さないでというか、HUDのメッセージの行に出すとかで、固定レイアウトで。スクリーンセーバー的に定期的に再取得しに行って最新の速報を出し続ける

続けて施主は「アプリ起動したら全画面クリアして最上部に描画のイメージなんだ」と言った（ADR 0006 では、プロンプトの下に帯を確保して、上のシェルの履歴を残していた）。

上流指示の進め方では「取得を裏で」は手順 4 だったが、施主の使い方の核なので前倒しする（記事の保存は手順 4 に残す）。
並行性は使えない（SWF-013・CNF-022）ので、取得の子プロセスを「待たずに起動し、表示のループの待ちで一緒に待つ」形が要る。

## 決定

0. **帯の置き方**（ADR 0006 の 1・3・4・5 を置き換え）: 起動したら alternate screen に入って画面を全部消し、帯を**最上部**（1〜15 行目）に描く。位置は絶対で指す（`ESC [ 行 ; 1 H`）。
   帯の下は空けておく。終わるとき（`q`・Ctrl+C・SIGTERM・SIGHUP・異常終了のシグナル）は色とカーソルとエコーを戻して alternate screen から出る（起動前の画面に戻る）。
   大きさが変わったら画面を消して全部を描き直す
1. **帯の外に何も書かない**。起動したらすぐ帯を描き、記事が届くまでは枠の中に「回線を確立中」を出す（FR-20）。取得の進み具合の行は出さない
2. **固定の割り付け**（15 行・ADR 0006 の 2 を置き換え）: 見出しの行・枠の上辺・記事と DATA の窓の **10 行**・枠の下辺・**メッセージの行**（`MSG ›` に続けて、取得中・取れた件数と新着・更新なし・失敗の理由と取り直すまでの分）・状態の行
3. **DATA の窓**はフィードごとに 1 行: 印（取りに行っている最中 `~`・取れた `●`・更新なし `●`（暗い）・失敗 `!`・未取得 `·`）・名前・件数（失敗は `ERR`）。文字の雨は手順 3 で、残りの行に降らせる
4. **裏での取得**: 予定は Core の `FetchSchedule`。1 度に取るのは 1 本だけ。起動時はどれもすぐ・取れたら **15 分**あけ（FR-07 の「15 分おき程度」）・失敗したら **2・4・8… 分（最大 60 分）**あけて取り直す。
   前の応答の `ETag` / `Last-Modified` があれば `If-None-Match` / `If-Modified-Since` を付けて取り、304 なら中身を取り直さない
5. **1 本のループ**: Host の `ChildProcess.start` が curl を起動して待たずに返し（`RunningChild`）、合成ルートの `Viewer` が `Console.waitForInput(watching:)` でキー入力と curl の出力の読み口を一緒に `poll` する。
   起きたら `RunningChild.pump()` で読めるだけ読み、両方の読み口が閉じたら結果を受け取る。終了するときは走っている curl に SIGTERM を送って待つ
6. **巡り**（Core の `Rotation`・FR-12）: フィードごとに最後に取れた記事だけを持つ（一晩流しても増えない・FR-02）。一周したら最新の内容で並べ直す。
   - 取り直して**新しく現れた記事は速報**として次の 1 件に割り込み、受信の行に `速報` の印を付ける（上限 20 件・新しい順）
   - フィードの**初回**の記事は速報にせず、いまの一周の残りに混ぜる（起動直後の一周が最初に届いたフィードだけにならない）
   - 記事が 1 件も無い間は締め切りを数えず、最初の記事が届いたらすぐ見せる

## 強制

- **active** → CNF-022（並行性の禁止。待つのは合成ルートの 1 本のループだけ）＋CNF-023（子プロセスの起動は Host だけ）
- テストで確かめる（`make check` の `test` 段）: 起動時の予定・1 本ずつ・15 分・304 で手がかりを残す・失敗の倍々と上限・
  巡りの割り込みと初回の混ぜ方・手がかりのヘッダの付け方・待たずに読める子プロセスと止め方・帯の固定の割り付け（メッセージの行・DATA の窓・速報の印・回線を確立中）
- 実機で確かめた（2026-10-26・Windows Terminal・120×30）: 起動すると画面が消えて最上部に帯が出る。帯の外に何も出ず、取得の様子がメッセージの行と DATA の窓に出る。
  擬似端末で、`→`・空白・`q`／SIGTERM／SIGSEGV／大きさの変更（120→80→60×10）のどれでも alternate screen から出て termios が起動前と同じに戻る。取得の最中に `q` で終わると curl も止まる

## 結果

- 起動したら放っておくだけで、新しい記事が取れしだい速報として流れる。終わればシェルの画面が起動前のまま戻る
- 失うもの: 起動のたびに一から取る（記事の保存は手順 4）。一度に 1 本ずつなので、フィードが多いと一巡に時間がかかる（1 本 20 秒で打ち切る）

## 却下した選択肢

| 選択肢 | 却下の理由 |
| --- | --- |
| 帯をプロンプトの下に置き、上のシェルの履歴を残す（ADR 0006） | 施主が「全画面クリアして最上部に描画」と決めた。絶対位置で描けるので、大きさの変更で帯の跡がずれて残る問題も無くなる |
| 取得の進み具合を帯の上に行として残す（ADR 0006 の 10） | 施主が「取得ログとかは残さないで」と決めた |
| 取得をスレッドや `async` で回す | 並行性の禁止（SWF-013）。子プロセスの読み口を `poll` で待てば足りる |
| 全部のフィードを同時に取る | 礼儀正しく取る（FR-07）。表示に急ぐ理由が無い |
| 取得の間隔をもっと短くする（数分おき） | FR-07 が「15 分おき程度」で、短い間隔で何度も取りに行かない |
| 新しい記事を一周の最後に足すだけにする | 「最新の速報を出し続ける」に合わない（一周が長いと何分も出ない） |
